# 运营手册 · 赫同学工作台

> 一个人、一张页面、四条内容线。目标是让“看得见的作品”替代自我介绍。

## 一、定位

**一句话**：把 AI 影像从“生成”拉回“导演”的教学者与实践者。

不做的事：不追热点复述、不写“AI 将取代谁”、不发无法验证的数据。做的是：一镜一镜拆给你看，一个工作流一个工作流交给你用。

## 二、受众与他们在找什么

| 受众 | 他们搜什么 | 页面里对应的落点 |
| --- | --- | --- |
| 同行教师 | AIGC 课程怎么开、课件怎么排、教案怎么写 | 课堂三件套、课堂课件共建、30 天课纲 |
| 学生与创作者 | 怎么让 AI 视频不像 AI、分镜怎么写 | 故事导演 Skill、三支柱、单场景试片 |
| 合作方 | 能不能定制、怎么联系、交付什么 | 合作区四格 + Issue 模板 |

## 三、内容四支柱

1. **作品**：开源互动页面、短片、系列微短剧。一个作品一篇复盘，写清“为什么这么做”。
2. **工作流**：一条 Skill 一篇说明——输入什么、判断什么、产出什么、怎么检查。
3. **方法**：三支柱的单项拆解。每篇只讲一个原则，配一组错误 / 正确对照。
4. **课堂**：真实课时、真实学生反应、真实的失败镜头。教学现场是难被复制的素材。

## 四、渠道与改写规则

| 渠道 | 形态 | 改写要点 |
| --- | --- | --- |
| GitHub | 仓库 + Pages + Issues | 说明文档优先；Issue 当需求池 |
| 小红书 | 单图 + 短说明 | 只讲一个反常识结论，配 3 张过程图 |
| 公众号 | 1500–2500 字复盘 | 保留失败过程与方法依据 |
| B 站 / 视频号 | 3–8 分钟拆片 | 先放成片，再倒推决策点 |
| 课堂 | 两课时 90–100 分钟 | 与站点内容互为素材，不重复造 |

一条内容的生产顺序：**课堂或作品里发生 → 站点记录 → 长文复盘 → 拆成短图文 → 回到课堂当案例**。

## 五、节奏

- 每周：1 条工作流说明（GitHub / 站内）+ 1 条短图文。
- 每两周：1 篇作品复盘长文。
- 每月：1 次站点数据与文案体检（见第七节）。
- 每学期：1 套课程资产（三件套）与 1 支成片。

## 六、指标（按顺序看，别跳步）

1. **打开率**：站点访问来源（GitHub 仓库页 → 站点占比）。
2. **留存信号**：Skill 筛选点击、作品外链点击。
3. **信任信号**：Star、Issue、PR。
4. **商业信号**：说着“场景 + 交付物 + 时间”的咨询有几条。

不追粉丝数，先追“有人照着做出来了”。

## 七、每月迭代 SOP

- [ ] 首屏三行文案还准不准（身份、作品、方法是否有变化）
- [ ] 数字与事实一致：工作流总数、上架条数、仓库数
- [ ] 断链检查：作品外链、GitHub 链接
- [ ] 移动端 390px 宽度下无横向滚动、无字号过小
- [ ] 新增作品 / 工作流是否进了对应区块与筛选分类
- [ ] 数据带是否仍能实时读取（接口失败时显示“—”）

## 八、合规红线

- 不虚构数据、学生反馈、媒体背书；引用他人方法论必须注明（2XLabs《合龙》、野也也团队复盘、Seedance 2.0 Skill OS）。
- 学生作品、课堂影像对外发布前取得同意；不出现可识别的学生个人信息。
- 涉及单位、职称、合作价格的表述以本人确认为准，站点默认只写“高校教师”，不写单位全称。
- 作品与图文不使用平台“AI 生成”水印标识；生成类内容在说明里如实交代用了什么模型。
